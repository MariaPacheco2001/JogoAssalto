# Validação por issue

Cada plano define preparação, passos, resultados esperados e evidência a recolher. As execuções manuais estão pendentes até serem registadas pela equipa; documentação acrescentada não equivale a funcionalidade concluída.

A issue #1 tem o [Scope Document preenchido](../Golpe-Calculado-Scope-Document.docx), revisto em seis páginas no Word, no commit 0c8563c. As restantes 69 issues têm um plano individual e um commit de documentação associado.

## Como registar uma sessão

1. Selecionar a issue e confirmar dependências.
2. Registar commit, build e computador.
3. Executar os passos e preencher resultados, sem marcar casos não realizados.
4. Ligar evidência na issue e criar um commit da alteração correspondente.
5. Repetir os casos afetados por correções antes de concluir a tarefa.
